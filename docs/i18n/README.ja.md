**Windows** 上の [opencode](https://opencode.ai) エージェントのための書き込みサンドボックスと緊急停止機能です。プロジェクトフォルダー内でエージェントを無人で作業させるためのものです。管理者権限、Docker、WSL、ネットワークアクセスはいずれも不要です。

![スクリプト化されたエージェントが自分のフォルダーの外に書き込もうとしてプラグインと Windows に拒否され、その後キーファイルを読んで、ユーザーがメッセージを書くまですべてのエージェントを停止させる](../media/demo.gif)

*隔離された `opencode serve` 上で、実際のプラグインとランチャーに対してスクリプト化されたエージェントを動かしたものです。*

| 構成要素 | 機能 |
|---|---|
| **サンドボックス** (`win-guard-sandbox.js` + ランチャー) | エージェントはすべてを読めますが、書き込めるのはプロジェクトフォルダー内だけです。`edit`/`write` については、プラグインが実際のパス(リンクを解決したもの)を確認します。シェルについては、**Windows 自身**がフォルダー外への書き込み、削除、権限変更をすべて拒否します。コマンドは Low 整合性レベルのトークンで実行され、Low ラベルが付いているのはプロジェクトフォルダーとキャッシュフォルダーだけです。 |
| **秘密ファイル** (ランチャー、`secrets.txt`) | キーやパスワードを含むファイル(SSH キー、クラウドの認証情報、ブラウザーのキー、opencode 自身のサービスパスワード...)には、Low のプログラムが越えて読み取ることのできない強制ラベルが付けられます。あなた自身のプログラムには影響しません。 |
| **制限** (ランチャー) | すべてのコマンドはジョブオブジェクト内で実行されます。あなたのために一定量の RAM を常に空けておく厳格なメモリ上限、ディスク空き容量の下限、プロジェクトとキャッシュを合わせたサイズの上限があります。制限を超えるとコマンドは終了されます(終了コード 125)。 |
| **キルスイッチ** (`win-guard-killswitch.js`) | すべての呼び出しを**実行前に**確認します。対象はシェルコマンドと、それが起動するプロジェクトのスクリプト(`build.ps1`、`npm test` のスクリプト...)です。明らかに有害な呼び出し(キーの読み取り、保存済みパスワードの Windows への要求、ディスクの消去、Defender の無効化、外部からの opencode の操作...)は、**そのフォルダーのすべてのエージェント**を即座に停止させます。危険を伴う呼び出し(中身を確認せずにスクリプトをダウンロードして実行する、ファイルのアップロード、自動起動の登録)は拒否されます。プロジェクト内の `STOP` ファイル、多数の拒否された呼び出し、プロジェクトのファイルの大部分の消失によっても停止します。停止状態は opencode を再起動しても、あなたがメッセージを書くまで続きます。 |

これはエージェントのミスや、エージェントが言いくるめられて実行しうる有害なコマンドから守るものです。脱出するために書かれたプログラムに対する壁ではありません。頼りにする前に[セキュリティモデル](../security-model.md)を読んでください。

## 動作要件

- Windows 10 または 11、NTFS。
- opencode 2.2 以降(V2 プラグイン API)。Windows 10 22H2 上の opencode 2.2.3 でテスト済みです。
- .NET Framework 4 の C# コンパイラー(`%SystemRoot%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`)。Windows の一部なので、何もインストールする必要はありません。インストーラーは [`launcher/`](../../launcher) のソースからランチャーをビルドし、ビルド済みのプログラムはダウンロードしません。
- bash を使う場合: Git for Windows。Git Bash は自分専用のコピーからでないと Low 整合性で起動しないため、インストーラーはそれ(約 400 MB)をサンドボックスフォルダーにコピーします。Git がない場合(`-NoGit`)、エージェントは PowerShell と cmd を使います。

## インストール

[最新リリース](https://github.com/retretor/opencode-win-guard/releases/latest)のソースをダウンロードし(またはリポジトリをクローンし)、PowerShell で次を実行します:

```powershell
cd opencode-win-guard
.\install.ps1 -Folder C:\Users\me\Projects\my-project
```

インストーラーは、ランチャーを `~\.local\share\opencode\sandbox\bin` にビルドし、Git をコピーし、`secrets.txt` と `~\.config\opencode\win-guard.json` をサンプルから作成し(既存のものはそのまま残します)、プラグインを `~\.config\opencode\plugins` にコピーし、`secrets.txt` に記載されたファイルを閉じます。その後:

1. **`~\.local\share\opencode\sandbox\secrets.txt` を読み**、あなたのコンピューター上のキーやパスワードを含むファイルを追加します。`bin` フォルダーにある `protect.exe --list` で、何が閉じられているかを確認できます。
2. opencode を再起動し、プロジェクトフォルダーでセッションを開始します。ログ `~\.local\share\opencode\log\win-guard.log` に `on for <folder>` と記録されます。

更新するには `install.ps1` をもう一度実行します。すべてを削除するには `uninstall.ps1` を実行します(`-RemoveData` を付けると Git のコピー、キャッシュ、設定も削除します)。PowerShell がスクリプトの実行を拒否する場合は、`powershell -ExecutionPolicy Bypass -File .\install.ps1 ...` で起動してください。

## 設定: `~\.config\opencode\win-guard.json`

```json
{
  "folders": ["C:\\Users\\me\\Projects\\my-project"],
  "limits": { "ramFreeGB": 4, "diskFreeGB": 15, "folderGB": 15 },
  "agents": "*",
  "extraTools": [],
  "alsoWritable": [],
  "lowLabel": [],
  "env": {},
  "language": "en"
}
```

| キー | デフォルト | 意味 |
|---|---|---|
| `folders` | (必須) | 絶対パス。このいずれか(またはその配下)で開始されたセッションが保護されます。それ以外の場所では何も変わりません。ドライブ全体、ユーザーフォルダー、システムフォルダーは拒否されます。 |
| `limits.ramFreeGB` | 4 | 常にあなたのために空けておくメモリ。コマンドは開始時にこの空きができるまで最大 60 秒待ち、空きメモリがこれを下回ると終了されます。 |
| `limits.diskFreeGB` | 15 | フォルダーのあるドライブで確保しておく空き容量。 |
| `limits.folderGB` | 15 | フォルダーとそのキャッシュを合わせた最大サイズ。 |
| `agents` | `"*"` | 保護対象のエージェント: すべてなら `"*"`、または名前のリスト。それ以外のエージェント(たとえばあなた自身の対話用エージェント)はフル権限で動作します。リストを指定した場合、保護対象のエージェントはそのリストにあるサブエージェントしか起動できません。 |
| `extraTools` | `[]` | エージェントが使ってよい、ほかのプラグインのツール。何も書き込まないとわかっているもの以外のツールはすべて拒否されます。新しいプラグインや MCP サーバーはフル権限で動作するためです。名前を追加するのは、そのツールが何も書き込まないか、自身の書き込みを自分でチェックする場合だけにしてください。例: [opencode-crew-mail](https://github.com/retretor/opencode-crew-mail) 用の `["crew_list", "crew_send"]`。 |
| `alsoWritable` | `[]` | `edit` と `write` が変更できる追加のフォルダー(シェルは対象外)。 |
| `lowLabel` | `[]` | Low ラベルを付ける追加のフォルダー。サンドボックス内のプログラムがそこに書き込めるようになります。パスは `%APPDATA%`、`%LOCALAPPDATA%` などの環境変数で始めることができます。プロジェクトでビルドしたプログラムのデータフォルダーに便利です。そうしたプログラムは権限を下げた状態で動作し(あなた自身が起動した場合も同様)、設定やセーブデータを書き込めないと失敗することがあります。存在しないフォルダーは作成されます。 |
| `env` | `{}` | サンドボックス内のコマンド用の追加の環境変数。例: `{ "CARGO_HOME": "${cache}/cargo" }`。`${cache}` はプロジェクトのキャッシュフォルダー、`${folder}` はプロジェクトフォルダーです。サンドボックスはすでに npm、yarn、pnpm、bun、pip、uv、Poetry、Go、Gradle、NuGet、.NET のキャッシュと、`TEMP`、`APPDATA`、`LOCALAPPDATA` をそこへ移しています。 |
| `language` | `"en"` | 停止メモの言語: `"en"`、`"zh-CN"`、`"ja"`、`"ko"`、`"es"`、`"pt-BR"`、`"de"`、`"fr"` または `"ru"`。ほかの言語の追加も歓迎します。[CONTRIBUTING.md](../../CONTRIBUTING.md#translations) を参照してください。 |

設定ファイルが壊れていてもガードはオフになりません。シェルは拒否され、ログにその理由が書かれます。

## エージェントに見えるもの

- セッションごとに 1 回、どこに書き込めるか、秘密ファイルは開けないこと、制限の内容、有害な呼び出しをすると全員が停止することが伝えられます。
- 拒否されたツール呼び出しは、理由付きで `Blocked: ...` を返します。Windows による拒否は、シェルでは "Access denied" として表示されます。
- ランチャーの終了コード: **125** 制限または `STOP` によってコマンドが終了された、または実行が阻止された。**126** コマンドが起動されなかった(サンドボックスが不完全)。その代わりにコマンドがフル権限で実行されることは決してありません。
- 緊急停止後は、すべての呼び出しが `EMERGENCY STOP: <reason>` で失敗し、エージェントは中断され(リードが先)、プロジェクト内の `AGENT_STOPPED.txt` に何が起きたかが書かれます。`STOP` ファイルを作成した場合はそれを削除し、そのフォルダーのセッションで何かメッセージを書いてください。

## 自分でエージェントを止める

プロジェクトフォルダーに `STOP` という名前のファイルを作成します。実行中のコマンドは 1〜2 秒以内に終了され、新しいコマンドは開始されず、そのフォルダーのすべてのエージェントが中断されます。

## ほかのプラグインとの連携

- `globalThis[Symbol.for("opencode-win-guard.halted")]` は、停止中のフォルダー(小文字、スラッシュ区切り)の `Set` です。エージェントを自動的に続行させるプラグイン(オートパイロット)は、まずここを確認してください。
- ほかのプラグインのツールには `extraTools` が必要です。上記を参照してください。

## ランチャーが C# で書かれている理由

サンドボックスには、どのスクリプトからも直接呼び出せない Windows の機能が必要です。Low 整合性レベルの制限付きトークン、`CreateProcessAsUser`、メモリ制限付きのジョブオブジェクト、そしてファイルへの強制ラベルです。C# なら素の P/Invoke でこれらを呼び出すことができ、そのコンパイラーは .NET Framework の一部としてすべての Windows 10 と 11 に付属しています。そのため、ランチャーはインストール時にあなた自身のコンピューター上で、読みやすいソースからビルドされます。SDK もダウンロードも、インターネットから取得した署名なしのプログラムも必要ありません。この古いコンパイラーでビルドできるように、コードは C# 5 の範囲に限定しています。

## テスト

```powershell
npm test                                   # pure parts, any OS
$env:WIN_GUARD_E2E = "1"; npm run test:e2e # also the launcher and both plugins in a real `opencode serve` with a fake model
```

エンドツーエンドテストは、専用の秘密ファイルを持つ一時フォルダー内で動作し、ランチャーを自前でビルドし、設定したラベルはすべて元に戻します。あなたの opencode 設定、セッション、サンドボックスには触れず、プロバイダーやアカウントも必要ありません。

## 関連プロジェクト

2026 年 11 月時点で見つかったものです。いずれも Windows 上でシェルをサンドボックス化したり、セッションツリー全体を停止したりはしません:

- [opencode-sandbox](https://github.com/Hamza-Abili/opencode-sandbox): bubblewrap(Linux)と Seatbelt(macOS)を使ったシェル用の OS サンドボックス。ネイティブの Windows はサポートされていません。
- [opencode-guard](https://github.com/gigi206/opencode-guard): ツール呼び出しに対するルールベースの deny/ask と任意の判定モデル、そしてモデルに届く前の秘密情報の墨消し。
- [opencode-hook-safety](https://github.com/MansM/opencode-hook-safety): 秘密のパスと破壊的なコマンドの拒否リスト、任意の分類器。
- [opencode-damage-control](https://github.com/nicounii/opencode-damage-control): 90 以上の危険なコマンドパターンをブロックし、3 段階のパス保護を備えます。

これらはコマンドテキストとパスのレベルで動作します。オペレーティングシステム自身による拒否を加えるこのプラグインと、うまく組み合わせて使えます。
